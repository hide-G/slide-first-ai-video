# React frontend and X teaser short-video pipeline

This change adds two major subsystems: a React SPA frontend (Vite + AWS Amplify Cognito auth, project CRUD, slide generation/preview/approve workflow, video progress polling, deliverables) and a Phase 2 teaser pipeline for generating short-form X videos from presentation slides. The teaser pipeline chains Bedrock-driven slide selection, hook/post text generation, Polly narration, Hyperframes HTML composition (both 16:9 and 9:16 slide-card formats), and rendering via the existing render state machine. CDK infrastructure adds frontend hosting (S3 + CloudFront), three teaser constructs, and an API endpoint.

Watch for: The teaser state machine receives no `slides` array in its initial input — the teaser-generator Lambda expects slides but nothing fetches them (confirmed). The 9:16 render path is sequential after 16:9, not parallel, doubling render wall-clock time. Frontend auth guard relies on a `navigate()` call during render, which is a React anti-pattern that may flash protected content before redirecting.

**Verdict**: NEEDS_CHANGES

## High-level view

The frontend is a minimal SPA shell: Amplify Authenticator for login, a Layout wrapper that checks auth, page components for project CRUD, slide generation, version preview/approve, and video generation with polling. The auth guard redirects during render rather than using a declarative `<Navigate>`, and the video version is hardcoded to `1` in the UI.

The teaser pipeline is a three-Lambda Step Functions workflow: teaser-generator (Bedrock Converse for slide selection, hook text, post text), Polly map for narration, and teaser-composition-builder (Hyperframes HTML for 16:9 and 9:16 slide-card). Duration validation logic exists in `packages/core` with a 30-60 second target window but is never invoked in the pipeline.

The CDK integration wires the teaser state machine ARN into the API Lambda, adds the `/videos/teaser` route, and deploys a frontend S3+CloudFront distribution with SPA error-page routing. The Bedrock IAM policy uses `Resource: "*"` rather than scoping to the specific model ARN.

## Teaser state machine input gap

The teaser API handler (`lambdas/api/src/handlers/teaser.ts` lines 99-105) constructs an execution input with `projectId`, `userId`, `versionNumber`, `jobId`, and `outputTypes`. The teaser-generator Lambda's handler destructures `event.slides` (from `TeaserGeneratorEvent`) and passes it directly to `selectTeaserSlides`. Nothing in the state machine definition fetches the manifest from S3 before invoking the Lambda. The Lambda itself has no S3 import or getObject call.

The teaser-generator will receive `slides: undefined`, and `selectTeaserSlides(undefined, selectedNumbers)` will throw at runtime when calling `.find()` on undefined.

Fix: Either add a "FetchManifest" Lambda task as the first step of the teaser state machine that reads the manifest from S3 and injects the slides array into `$.slides`, or modify the teaser-generator Lambda to accept `s3Bucket`/`s3Prefix` and fetch the manifest itself (it already has S3 read permissions via CDK).

## Sequential 9:16 path doubles render time

The state machine definition chains steps sequentially:

```
generateTeaser -> pollyMap -> buildComposition16x9 -> startRender16x9 -> buildComposition9x16 -> startRender9x16
```

The 16:9 and 9:16 paths are independent after Polly completes. With `IntegrationPattern.RUN_JOB`, each render waits for the child execution to finish before proceeding. A `Parallel` state after Polly containing [16x9 composition + render] and [9:16 composition + render] would halve total pipeline duration.

## Bedrock IAM scope

```typescript
// infra/lib/teaser-generator-construct.ts, line 44-49
new iam.PolicyStatement({
  effect: iam.Effect.ALLOW,
  actions: ["bedrock:InvokeModel"],
  resources: ["*"],
})
```

This grants invoke-model access to every foundation model in the account. The `BEDROCK_MODEL_ID` is known at deploy time, so the resource can be scoped to `arn:aws:bedrock:*::foundation-model/${modelId}`.

## Frontend auth guard during render

In `Layout.tsx`:

```tsx
if (!isAuthenticated) {
  navigate("/login");
  return null;
}
```

`navigate()` is a side-effect during the render phase. React 18 strict mode will double-invoke this. The component briefly mounts (flashing `null`) before navigation takes effect. Replace with `<Navigate to="/login" replace />`.

## Hardcoded versionNumber in video generation UI

`VideosPage.tsx` always passes `{ versionNumber: 1 }` to both `startVideo` and `startTeaser`. This breaks for multi-version projects. The page should receive the version as a route parameter or fetch the project's `currentVersion`.

## Duration validation not wired into the pipeline

`packages/core/src/teaser/duration.ts` exports `validateTeaserDuration` which checks the 30-60 second range. The teaser-generator Lambda calculates `totalDurationMs` in its return value but never validates it. If Bedrock selects slides totaling 90 seconds, the pipeline builds and renders an over-length video. The Lambda should validate and re-select (e.g., drop the longest slide until within range), or the state machine should include a Choice state that fails on invalid duration.

## Polling lifecycle in JobProgress

If `pollJob` encounters a network error, the interval is cleared and the component shows an error permanently with no retry. For transient failures, a manual "Retry" button or automatic retry with backoff would prevent the user from having to refresh the page.
