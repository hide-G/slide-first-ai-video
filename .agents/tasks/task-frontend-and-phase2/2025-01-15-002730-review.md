# React frontend and X teaser pipeline (v2)

This change adds a React SPA frontend (Vite, AWS Amplify Cognito, project CRUD, slide workflow, video progress, deliverables) and a Phase 2 teaser pipeline (Bedrock-driven slide selection, hook/post text generation, Polly narration, Hyperframes HTML composition in 16:9 and 9:16, rendering via the existing render state machine). CDK infrastructure includes frontend hosting (S3 + CloudFront), teaser constructs, and a new API endpoint. All six issues from the v1 review have been addressed: the teaser-generator Lambda now fetches the manifest from S3 directly, renders run in Parallel, Bedrock IAM is scoped to the model ARN, the auth guard uses `<Navigate>`, version comes from `useSearchParams`, and duration validation is called in the pipeline.

Watch for: The frontend's `listProjects` call hits `GET /v1/projects` but no such route exists in the API — the projects page will always 404 (confirmed). The teaser state machine's execution input from the API handler is missing `s3Bucket`, `s3Prefix`, `assetsPrefix`, `voiceId`, `engine`, and `sampleRate` fields that downstream steps reference via JSONPath — Polly and composition-builder steps will receive null for these values (confirmed). The `LoginPage` calls `navigate()` during render inside a render prop callback, which is a side-effect that can trigger React warnings and flash behavior (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The frontend relies on an API endpoint (`GET /v1/projects`) that doesn't exist. The projects list page — the first thing a user sees after login — will fail immediately with a 404.

The API handler that starts the teaser pipeline passes an incomplete execution input: it provides `projectId`, `userId`, `versionNumber`, `jobId`, and `outputTypes`, but the state machine's Polly and composition-builder steps reference `s3Bucket`, `s3Prefix`, `assetsPrefix`, `voiceId`, `engine`, and `sampleRate` from the top-level state — all of which will be undefined at runtime.

The `LoginPage` performs an imperative `navigate()` inside the `Authenticator` component's render-prop callback. This fires during the render phase on every re-render when the user is authenticated, potentially causing React strict-mode double-invocation and a brief flash before navigation.

## Missing list-projects API route

The `frontend/src/pages/ProjectsPage.tsx` component calls `apiClient.listProjects()` on mount, which issues `GET /v1/projects`. The API router in `lambdas/api/src/index.ts` defines only:

```typescript
{ method: "POST", pattern: /^\/v1\/projects\/?$/, handler: handleCreateProject, paramKeys: [] },
```

There is no GET variant. The route matcher returns null and the API responds with `{ error: "NOT_FOUND", message: "No route matches GET /v1/projects" }`. This makes the projects page — the landing page after login — non-functional.

A `handleListProjects` handler needs to be added (query DynamoDB by userId) with a corresponding `GET` route in the router.

## Incomplete execution input for teaser state machine

The teaser API handler at `lambdas/api/src/handlers/teaser.ts:99-105`:

```typescript
const executionInput = JSON.stringify({
  projectId,
  userId,
  versionNumber,
  jobId,
  outputTypes: ["x-teaser-16x9"],
});
```

The state machine definition references from the top-level input:
- `$.s3Bucket` and `$.s3Prefix` — used by Polly Map and both composition-builder invocations
- `$.assetsPrefix` — used by composition-builder to construct image URLs in the HTML
- `$.voiceId`, `$.engine`, `$.sampleRate` — used by Polly
- `$.ctaText` — used by composition-builder (optional, defaults to "Follow for more")

The subsequent steps receive these values via `sfn.TaskInput.fromObject({"s3Bucket.$": "$.s3Bucket", ...})` which will pass `null` into the Lambda event. Lambdas that construct S3 paths from these values will fail at runtime.

Fix: add `s3Bucket` (from env), `s3Prefix` (derivable from userId/projectId/version), `assetsPrefix`, and Polly config defaults to the execution input in the teaser handler.

## LoginPage render-phase side-effect

```tsx
<Authenticator>
  {({ user }) => {
    if (user) {
      navigate("/projects", { replace: true });
    }
    return <div>Redirecting...</div>;
  }}
</Authenticator>
```

The `navigate()` call fires synchronously during the render phase. In React 18 strict mode, this component mounts twice, calling navigate twice. Replace with `useEffect` or return a `<Navigate to="/projects" replace />` component.

## JobProgress permanent failure on transient errors

```typescript
} catch (err) {
  setError(err instanceof Error ? err.message : "Failed to get job status");
  if (intervalRef.current) {
    clearInterval(intervalRef.current);
  }
}
```

A single network timeout or 502 permanently stops polling. The job may still be running server-side but the UI shows a dead-end error with no recovery path. A retry counter (allow 3 consecutive failures before stopping) or a manual "Retry" button would make the UX resilient to transient failures.
