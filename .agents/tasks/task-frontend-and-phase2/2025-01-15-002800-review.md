# React frontend and X teaser pipeline (v3 — final pass)

This change adds a React SPA frontend (Vite, Amplify Cognito auth, project CRUD, slide workflow, video progress, deliverables) and a Phase 2 teaser pipeline (Bedrock slide selection and hook/post text, Polly narration, Hyperframes HTML composition for 16:9 and 9:16, parallel rendering). CDK infrastructure includes frontend hosting (S3 + CloudFront), three teaser constructs, and API endpoints for project listing and teaser generation. All ten issues raised in v1 and v2 have been addressed: manifest fetch in the Lambda, parallel renders, scoped IAM, declarative Navigate, version from search params, duration validation, list-projects route, complete state machine input, LoginPage Navigate, and JobProgress retry.

Watch for: No new blocking issues identified.

**Verdict**: APPROVED

## High-level view

The frontend is a minimal SPA shell covering project CRUD, slide generation/preview/approve, and video/teaser generation with polling. Auth is declarative (`<Navigate>` guard in Layout, `<Navigate>` redirect in LoginPage). The teaser pipeline chains three Bedrock Converse calls, a Polly map, and parallel 16:9/9:16 composition+render branches. Duration validation runs in the Lambda and surfaces warnings without blocking — an intentional soft gate. CDK wiring passes three state machine ARNs to the API Lambda and deploys frontend hosting with SPA error-page routing.

## Non-blocking observation: expired token handling

The `apiClient` fetches the ID token on every request via `fetchAuthSession()`. If the session is expired or the user is unauthenticated, `getAuthHeaders()` silently returns an empty object — the request proceeds without auth and receives a 401 from API Gateway's Cognito authorizer. The frontend shows a generic error message rather than redirecting to login. Acceptable for an MVP; a future iteration could intercept 401 responses and redirect to `/login`.
