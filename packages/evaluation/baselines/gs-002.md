# Introducing React Server Components

A new approach that moves component rendering to the server while maintaining interactivity.

<!-- presenterNote: React Server Components allow you to render components on the server, reducing bundle size and improving initial load performance. They integrate seamlessly with client components for interactive elements. -->
<!-- keyPoints: ["Server-side rendering for non-interactive parts", "Reduces client bundle size significantly"] -->

---

# How It Works: Data Fetching Example

```tsx
async function ProductList() {
  const products = await db.query('SELECT * FROM products');
  return <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}
```

<!-- presenterNote: Server components can directly access databases and APIs without exposing credentials to the client. The async/await pattern works naturally since execution happens on the server. -->
<!-- keyPoints: ["Direct database access in components", "No API layer needed for read operations"] -->

# Results: Bundle Size Reduction

- 40% smaller JavaScript bundle
- 2x faster initial page load
- No client-side data fetching waterfall

# Conclusion and Next Steps

- Server Components are production-ready in Next.js 14+
- Gradual adoption is possible (mix server and client)
- Start with data-heavy, non-interactive pages

<!-- presenterNote: The key takeaway is that Server Components are not all-or-nothing. You can incrementally adopt them starting with pages that primarily display data. This provides immediate performance benefits without a full rewrite. -->
